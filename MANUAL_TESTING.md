# Ручная проверка

## Запуск

Нужен Node.js 22.14+ и npm. В PowerShell:

```powershell
cd max-green-chat
npm ci
npm run dev
```

Команды запускаются из папки проекта с `package.json`. Если зависимости уже установлены, достаточно `npm run dev`.

Открой **http://127.0.0.1:5173** и оставь терминал запущенным.

## Интерфейс без аккаунта

Нажми «Открыть демо без токена». Проверь переключение между чатами, поиск, отправку локального сообщения и создание нового чата кнопкой «+». В узком окне браузера после открытия чата должна появляться кнопка возврата к списку.

Демо проверяет только интерфейс: в нём нет настоящей отправки и ответов из MAX.

## Подготовка реальной переписки

Для полного сценария нужны **два аккаунта MAX**: аккаунт A, подключённый к GREEN-API, и аккаунт B на втором телефоне или у человека, согласившегося помочь с проверкой. Из веб-приложения A пишет B, а B отвечает через обычный MAX. Переписка с самим собой не заменяет этот сценарий.

В [личном кабинете GREEN-API](https://console.green-api.com/):

1. Создай или выбери инстанс **MAX**, авторизуй аккаунт A и дождись состояния `authorized`.
2. Скопируй `apiUrl`, `idInstance` и `apiTokenInstance` этого инстанса.
3. Включи входящие сообщения: `incomingWebhook: yes`.
4. Оставь `webhookUrl` пустым: приложение получает события через HTTP API.
5. Для статусов доставки/прочтения дополнительно включи `outgoingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook`; для состояния инстанса — `stateWebhook`.
6. Сохрани настройки и дай сервису время применить изменения. Закрой другие приложения/вкладки, получающие очередь того же инстанса.

Токен вводится только в форме подключения приложения. В исходники или GitHub его добавлять не нужно.

## Обязательный сценарий ТЗ

| Действие | Ожидаемый результат |
| --- | --- |
| Выйти из демо, заполнить три поля и подключиться | Открывается список чатов без ошибки авторизации |
| Нажать «+» и ввести номер аккаунта B с кодом страны | Создаётся и открывается чат |
| Отправить «Проверка исходящего сообщения» | Текст появляется справа и приходит B в обычном MAX |
| Из аккаунта B ответить «Проверка входящего ответа» | Ответ автоматически появляется слева в том же веб-чате |
| Отправить несколько сообщений в обе стороны | Сообщения не теряются, не дублируются и попадают в правильный чат |

При пустой очереди первый long polling может показывать «Подключение…» до 30 секунд. Новое событие завершает ожидание раньше.

**Успешная интеграционная проверка** — исходящий текст действительно получен B, а его ответ появился в веб-приложении. Пузырь сообщения или галочка принятия API сами по себе не подтверждают доставку.

## Дополнительные проверки

| Проверка | Ожидаемый результат |
| --- | --- |
| Enter / Shift+Enter | Отправка / новая строка |
| Пустая строка или пробелы | Отправка недоступна |
| Текст до 4000 символов | Поле ограничивает длину, текст переносится |
| Ответ со ссылкой | Входящий текст отображается |
| Добавить тот же телефон повторно | Открывается существующий диалог |
| Второй собеседник пишет в неактивный чат | Появляется счётчик непрочитанных, при открытии он сбрасывается |
| Обновить страницу и подключить тот же инстанс | Токен вводится заново, история этой вкладки восстанавливается |
| Отключить интернет, подождать, восстановить связь | Получение переподключается автоматически с задержкой до 30 секунд |
| Нажать «Выйти» | Возвращается форма, запросы этого подключения прекращаются |
| Ввести неправильный токен | Ошибка доступа, чат не открывается |

Отключение сети можно проверить через DevTools → Network → Offline. Затем верни **No throttling**. При сетевом сбое во время отправки сначала проверь MAX на втором аккаунте: сообщение могло уйти, даже если ответ API не дошёл до браузера.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| Нет запуска | Node.js, папку с `package.json`, `npm ci`, доступ к npm |
| Порт занят | Закрыть предыдущий сервер или запустить `npm run dev -- --port 5174` |
| Ошибка входа | Все три поля относятся к одному MAX-инстансу, состояние `authorized` |
| Номер не найден | Код страны, наличие MAX у B, настройки поиска по номеру и ограничения MAX |
| Отправка есть, ответа нет | `incomingWebhook: yes`, пустой `webhookUrl`, отсутствие второго потребителя очереди |
| CORS / Failed to fetch | Точный `apiUrl`, сеть и разрешение origin на стороне GREEN-API |
| Ошибка истории | Доступность и свободное место `sessionStorage` |

В Network браузера токен присутствует в URL по протоколу GREEN-API. Скриншоты для рекрутера делай без раскрытого токена и Network-запросов.
